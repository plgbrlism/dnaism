# managing skills

one-line summary: how to add, edit, delete or improve a skill, and every file that must follow.

## anatomy

a skill is `skills/<name>/SKILL.md`, under 100 lines.

| part | rule |
|---|---|
| frontmatter | `name` and `description` only, no other keys |
| name | matches the folder, kebab-case |
| description | one line, says what it covers and when to load it |
| body | `# <name>`, then `one-line goal:`, then tables |
| size | under 100 lines, move detail to examples/ |

## update matrix

| action | files to touch | command |
|---|---|---|
| add | new `skills/<name>/SKILL.md`, root `SKILL.md` routing table, `rules/yap.md` `## skills` list, `README.md` skills table | `python3 scripts/sync-rules.py` |
| edit body | `skills/<name>/SKILL.md` | `bash scripts/check.sh` |
| edit description | `skills/<name>/SKILL.md`, plus any skill that references it | `bash scripts/check.sh` |
| rename | folder and `name:`, routing table, rules list, README, references in other skills and commands | `python3 scripts/sync-rules.py` then `bash scripts/check.sh` |
| delete | remove folder, routing row, rules name, README row, its command file if any, references in other skills and `tests/run.sh` | `python3 scripts/sync-rules.py` then `bash scripts/check.sh` |
| make invokable | `commands/<name>.toml` and `.opencode/command/<name>.md` | `bash scripts/check.sh` |
| improve | the skill, plus `corrections.md` | `bash scripts/check.sh` |

## where names live

| place | kind |
|---|---|
| `skills/<name>/SKILL.md` | hand |
| root `SKILL.md` routing table | hand |
| `rules/yap.md` `## skills` list | hand source |
| root `SKILL.md` rules block, 8 harness rule copies | generated by `scripts/sync-rules.py` |
| `README.md` skills table | hand |
| `.opencode/plugins/yap.mjs`, `scripts/list-skills.sh` | auto, scan `skills/` |
| root name in `SKILL.md` frontmatter | one source, `yap.mjs`, `scripts/link-skills.sh` and the checks read it |
| rules source stem in `rules/` | one file only, names the 8 harness copies |

## commands

| command | does |
|---|---|
| `python3 scripts/sync-rules.py` | regenerate the rule copies and the SKILL.md rules block, drop leftover copies from an old name |
| `bash scripts/check.sh` | lint: em-dashes, skill shape, rule copies, versions, skill lists |
| `bash scripts/check-skills.sh` | fail when a skill is missing from routing, rules or README |
| `bash tests/run.sh` | run check.sh on a clean copy and on broken copies |
| `bash scripts/list-skills.sh` | print every skill name and description |
| `bash scripts/link-skills.sh [dest]` | symlink skills into an agent skills dir |

## add a skill

```markdown
---
name: yap-new
description: New style. Load when <trigger>.
---

# yap-new

one-line goal: <one line>.
```

then add the name to the routing table, the rules list and the README, and run `python3 scripts/sync-rules.py`.

## improve a skill

| step | action |
|---|---|
| 1 | name the mistake in one phrase |
| 2 | pick the skill, or `rules/yap.md` if global |
| 3 | add or edit one rule as a table row |
| 4 | log a row in `corrections.md` |
| 5 | if `rules/yap.md` changed, run `python3 scripts/sync-rules.py` |
| 6 | run `bash scripts/check.sh` |
| prune | delete rules that never fire |
| overflow | past 100 lines, move detail into examples/ |

## never

- hand-edit generated copies, edit `rules/yap.md` and sync
- add frontmatter keys other than `name` and `description`
- leave a skill out of the routing table, rules list or README
